# 离线 0.8：功能核对、图像资源与模型纹理

依据 01 SRS、07 CAD、10 花纹、12 预览、18 测试、29 范围及实际代码重新核对。**项目尚未完成全部 48 项父需求或 Commercial 1.0 验收。** 用户已明确暂不接入 AI、商业授权和云服务，本轮补齐可独立运行的离线能力。“子用例通过”不能等同父需求完成。

## 本轮补齐

- 参考图支持 PNG/JPEG/WebP：原文件最大 64 MiB，解码总像素最大 4096²，任一边最大 16384 px，规范化 PNG 最大 72 MiB。先检查尺寸和有界元数据再解码，拒绝动态图片。
- 保留源文件原始字节、规范化 Original、512 px Proxy、128 px Thumbnail，各自记录尺寸、比例及哈希。EXIF 八种旋转/镜像保存显式矩阵；去方向元数据后再转换像素，避免重复旋转。标定点属于规范化 Original；代理点和轮廓通过实际比例还原毫米。
- 项目包保存独立图像文件并验证哈希；SQLite 的不可变图像和网格按内容哈希单独保存，命令/恢复/请求记录复用引用。资源和领域提交处于同一事务。丢失、篡改报错，旧内联快照继续读取。新版资源快照需要 0.8+，回退旧软件应使用旧项目包或备份库。
- 新建圆形、两点开放线段、圆角、倒角及六种缝线轮廓对齐。圆弧采用不超过 22.5° 的三次段，半径最大 1000 mm；独立径向误差小于 0.001 mm。相邻曲线、接缝、剪口或逐边缝份存在时拒绝角点修改。所有结果经过原生轮廓检查；开放路径可编辑，制造仍阻断。
- 静态 GLB 保留逐面角点 UV，几何焊接不合并 UV 接缝。最多 8 张、长边 2048 px 的不透明 base-color 纹理，UV 为 TEXCOORD_0 且在 [0,1]。颜色系数在线性域计算后编码回 sRGB，依据 [Khronos glTF 规范](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc)。外部图片、材质扩展、变换/平铺 UV、顶点颜色叠乘及透明材质超出子集，需要先烘焙。
- 接受展开后，在“花纹 / 模型 UV 纹理花纹”点击颜色，沿原 UV 裁剪至三角面并映射所有目标裁片。保留孔、反向 UV、跨片连续性及重复 UV 部位。分割基于 512 px 代理，细节仍需检查。
- 左侧预览可从任意正交方向“绘制三维花纹”：逐点绘制、撤回、闭合贴附；保存相机框架与源多边形，精确处理遮挡和跨片映射，失败/取消不提交，不插入虚构的制造源裁片。片内节点可逆映射，越域或单侧改变共享缝交点会拒绝。
- 点击 3D 花纹进入对应裁片和节点编辑；一对多绑定先选裁片。没有有效花纹记录的面可显示灰色，并报告面数，不推断颜色、不将部分花纹冒充整面覆盖。侧面可手绘补充。
- 侧面支持沿邻面延伸与指定 X 平面对称。延伸使用相邻面中心路径距离，只填充没有任何花纹记录的整面；来源必须触及共享边，跨分离部件不传播。对称要求 0.01 mm 内唯一顶点及精确镜像三角拓扑，不匹配就拒绝。结果保留来源哈希、算法、参数及 inferred provenance，必须在双视图检查并明确审核后才允许制造导出；审核可撤销，来源变化使结果失效。它不是语义推理，复杂边界应手绘。
- 任意正交视角支持闭合 Catmull–Rom 样条。可设置张力，保留原始节点和相机框架；三次曲线按控制点凸包距离上界 0.05 mm 离散，再执行精确可见面贴附。最多 400 源节点、2000 离散点，超预算或自交会拒绝。属于投影后附着曲线，不承诺跨曲面接缝处的内在曲率连续。
- 花纹锁定/解锁可撤销。编辑、重投影、删除由主进程保护；片内人工修改需明确确认后才能被重投影替换。
- WebGL 静态顶点缓冲负责纹理预览，相机变换和深度测试在 GPU 执行；先代理、后原纹理。设备/上下文失败回退 Canvas，可重试，领域状态不变。花纹覆层、热图、分区选择仍使用 Canvas/SVG；Canvas 纹理为仿射三角近似，制造和拾取使用独立精确映射。

## 使用和证据

根目录运行 `npm start`，或双击 `release/latest.json` 指向的便携程序。操作顺序：**模型 → 展开 → 裁片 → 花纹 → 制造**；左 3D、右 2D，参数在右侧工具区。

证据目录 [evidence/0.8.0](evidence/0.8.0)。`verification.json` 记录类型/单元/Rust/格式/Clippy/构建；`final-validation.json` 记录便携回归与构建哈希；`inference-e2e.json` 记录延伸、审核前导出阻断、批准后 SVG、撤销、锁定、样条、保存重启；`resources-e2e.json` 记录 4096 图像、EXIF、圆角/圆形、UV、GPU 像素/上下文丢失、三维手绘/拾取/锁定及重启回读。

桌面回归在执行环境使用测试专用 --no-sandbox；正式应用保持 sandbox:true。颜色聚类首轮点击落到吸顶工具说明上，已改为滚动至可见区域中部并检查实际命中 SVG，未放宽区域数量断言。抗锯齿代理含分离颜色回振，资源用例通过原始代理像素的连续中心矩形独立核验毫米尺寸，不假定降采样边界仍等于原图方块。

完整桌面回归也发现资源去重后缝份任务读取旧内联快照的问题，已改为读取会话修订号元数据，并新增带独立资源、切换活动项目后完成任务的回归；失败记录保留在 initial-desktop-failure.json 与 initial-ui-workflow-failure.log。

## 大项目开销修复

100 个曲线裁片的首轮拖动 p95 约 327 ms。移除未选中裁片的隐藏控制柄 DOM，按不可变对象缓存轮廓与切割路径，曲线边索引改为线性构建，避免为大领域数组逐项建立响应式代理。复测同一用例 p95 约 4.2 ms，仍需以最终构建报告为准。

164 MiB 综合包首轮打开约 80 秒。剖析显示后端约 8～10 秒，而工具区预先生成了十万顶点下拉选项。雕刻内容现按需挂载，顶点选择每页最多 200 项，全部顶点仍可通过页码或毫米中心选择。项目解压改为有最大输出长度的原生实现，仍保留目录、膨胀比、总量和哈希校验；会话内相同资源只读取一次，后台任务及修订检查直接读元数据。打开时复用已校验的几何，避免重复计算。最终冷打开和 20 次稳定内存以 full-performance.json 实测记录为准，不提前宣称达标。

大模型返回结果现通过隔离预加载接口传输 JSON 文本，渲染端只解析一次，避免 contextBridge 为数十万个域对象逐层复制和冻结。公共 API 仍是固定方法、不可改写的对象；主进程仍校验请求大小、方法/参数、来源窗口和帧，事件回调保留窄通道。没有暴露 Node、任意 IPC 或文件系统。

大纹理模型发生 GPU 失败时，默认回退到简化颜色网格并明确提示纹理暂不显示，避免在 Canvas 中逐面绘制 20 万个纹理三角。原始模型、纹理和精确拾取不变；可重试 GPU，或显式选择完整网格。小模型仍可用 Canvas 仿射纹理。

推断候选也可以在审核前逆映射修正；修正保留 inferred 来源并撤回旧审核，制造导出仍需重新确认。

## 最终构建实测

构建 `7ac0eba7` 的完整大项目基准已完成：100 个裁片、每片 100 个三次曲线段，拖动 p95 8.1 ms；20 万面和 2048 纹理下，实际帧计数变化的中位节奏约 119.7 FPS（并非物理显示器认证）。164 MiB 综合包冷打开 9.17 秒，20 次测量最大 9.07 秒，符合降级 10 秒，**不符合默认 5 秒**，因此 full-performance.json 的 passed 为 false。释放后内存末次/首次约 1.0030，未持续单调增长；释放状态采样合计最大 2.24 GiB，不能当作全程瞬时内存峰值。20 万面 GPU 上下文丢失、简化颜色回退、重试恢复及雕刻按需分页也通过，修订号保持不变。

同一构建的 145 项单元测试、6 项 Rust 测试、14 组便携桌面回归全部通过；Python 独立解析 SVG/PDF/DXF/GLB、项目包哈希、mask 面积和 Morph 重建检查通过。正常沙箱启动实测未通过：渲染/GPU 子进程启动失败（normal-launch.json/log），根因未确认；不能把测试专用 --no-sandbox 的通过当作正常系统验收。实体打印、缝制、试穿、完整安全/许可审核及 macOS/Linux 仍未验收。

后续用户实图回归、轮廓/布局/局部坐标缝份修复及最新构建 47992b03 的结果，见 [44-用户角色图双视图测试与修复](44-用户角色图双视图测试与修复.md)。上面的 7ac0eba7/145/14 为历史构建；最新为 149/6/15，大包冷打开约 8.36 秒，仍未达到默认 5 秒。
