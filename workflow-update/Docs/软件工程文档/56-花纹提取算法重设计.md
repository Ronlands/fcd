# 花纹提取算法重设计

日期：2026-10-08。实现目录：`D:\Codex\furrycad\workflow-update`。

## 为什么上轮测试通过仍然会有锯齿

旧测试覆盖圆形轮廓和几何有效性，没有覆盖不同斜率的细色带。旧实现直接对像素格边界做简化，再尝试贝塞尔拟合：容差小时仍追随台阶；提高容差后，端点选择又会让细条变宽，触发面积保护，整块退回原始台阶。默认只对大于 512 像素的手工 mask 平滑，使小图与自动提取的行为不一致。

本轮先建立失败回归：5 像素宽的斜色带旧处理仍有 80 个节点；不同斜率的进一步检查发现 36、134 个节点的退回情况。修改后的五种斜率均少于 20 个节点，并继续检查孔洞、自交与方向；专门的斜带测试还核对面积变化和曲线相对原像素边界的距离。

## 新流程

1. **保持原图坐标。** 自动双视图提取使用上传图片的原始分辨率，不用缩略图裁轮廓。原图像素统计上限与 4096×4096 输入预算一致，修正此前统计字段仍受 512×512 限制的问题。算法记录为 `illustration-2`，仍可读取旧记录。
2. **区分颜色和线稿。** 保留既有相邻近似色/阴影合并及大面积深色颜料检测。细暗线可以提供分隔证据，不直接当作一种毛皮颜色。
3. **保留色区实例。** 同色区域内部先移除线稿形成种子，再分别生长覆盖线稿像素；不同种子不会在填线后重新粘连。未形成完整分隔的短线不会凭空切开区域。微小种子不单独制造碎片。
4. **平衡台阶后拟合。** 对像素级凸凹阶梯进行局部平衡，保留长边形成的真实转角和用于分开对角接触的微小倒角，再简化轮廓。对端点拟合导致的面积偏移，沿有向面积梯度校正，累计位移限制在半个平滑像素预算内。
5. **验证后才采用。** 校正和曲线拟合继续检查自交、环方向、孔洞数量、孔洞关系、面积及复杂度。大拟合不能通过时逐步缩小预算重试。无法安全平滑的细节保留原始有效几何，不删除孔洞来换取外观；这意味着不能承诺每一个极小区域都一定成为光滑曲线。
6. **颜色区域与部位标签分离。** 新增独立的“角 / Horns”分类与模型组名识别，左右角匹配使用与耳朵一样的侧别约束。位置投票同时跨越头/耳、或外侧彩色突出部分缺少耳部证据时，标记为待分类，禁止自动贴到耳朵。部位标签不按横向比例硬切色块。
7. **人工纠错和制造确认。** 原图联合预览、钢笔节点、增加/减去选区和显式确认继续使用。含糊区域核对后设置角/耳朵及左右侧；缺失的边界使用钢笔定义。已生成的旧花纹不会随程序更新而自动改变，需要重新拆分。

自动拆分、手工 mask，以及界面中的 RGB/Lab/HSV 候选现在共用轮廓平滑处理。底层 RGB 像素洪泛仍保留默认的精确像素模式用于数值检查，界面入口显式启用拟合，避免把原始 mask 面积与拟合曲线面积混为一谈。传统 RGB/Lab/HSV 点击取色的栅格来源仍是 512 像素代理；需要原图细节时使用自动双视图提取或原图钢笔 mask，这部分未改成全分辨率聚类。

勾选显式 Bézier 拟合时，直接对原始边界执行其毫米容差拟合，不再先经过默认平滑，避免两次拟合导致曲线丢失。真实图片的擦除回归还暴露出另一问题：1–3 像素的孤立残点会让整批 mask 失败。现在保留有效区域，在候选中显示过滤像素数，原始 mask 和过滤记录随接受操作保存；若没有任何有效区域，仍拒绝生成空裁片。

## 各类痛点的处理边界

| 问题 | 本轮措施 | 仍需检查的情况 |
| --- | --- | --- |
| 斜边出现连续 90 度台阶 | 平衡台阶、面积校正、受检拟合，各入口统一 | 分辨率不足的极小图案、复杂细缝 |
| 角和耳朵同色且被粘在一起 | 线稿分隔后独立生长，角独立分类 | 线稿缺失、颜色完全相同且没有可见边界 |
| 角被归到耳朵并自动贴错 | 含糊分类保留为待分类，侧别校验 | 自动语义识别尚未实现，需人工确认 |
| 阴影形成碎片 | 相邻近似色合并，暗线与深色颜料分开 | 极重阴影、高光及真实相近色之间仍有歧义 |
| 毛尖、细条或孔洞被抹掉 | 原图提取、拓扑约束、接触点保护 | 小于原图分辨率的细节不能重建 |
| 前后图姿态不同、遮挡 | 保持来源独立，补全作为可编辑推断 | 不能从两幅图唯一恢复看不见的真实裁切边界 |
| 大图卡顿或大量碎片 | 像素/路径/区域数预算、后台任务与取消 | 没有将所有硬件和极端输入的性能视为已验证 |

“完美自动识别所有角色”不能由这些颜色和几何规则保证。本轮实现的是可以重现、检验和回退的几何修复与分区改进；部位识别仍是启发式建议，并未安装或训练语义分割模型。后续若要提高角/耳自动识别率，需要有逐部位标注的样本和独立评测集，不能把位置规则命中当成语义理解。

## 验证记录

新增固定回归覆盖五种斜率、原始边界偏差、面积、小尺寸 mask/RGB 候选、完整/不完整暗线、角组名、含糊头耳边界及原图统计。保留全体 3×3 连通形状的底层像素精确检查，以及平滑后几何有效性检查。

最终构建、完整检查与清理状态见同目录 `56-final-audit.json`。首轮桌面检查发现自动化点击没有把画布底部坐标滚入可视区；测试辅助方法现先滚动至目标并校验实际命中画布，不能以点击了错误位置后超时代表选区计算失败。

继续复测时，圆形聚类的显式 Bézier 拟合回归发现重复拟合丢曲线，真实 mask 擦除回归发现孤立残点中断；两项均修复后再检查。没有把首次失败的运行记为全部通过。

最终结果：273 项集成测试、6 项 Rust 测试、类型检查、Rust 格式、Clippy、构建及 33 套打包程序桌面回归全部通过。最终构建 SHA-256：`f5f0abeeaab87906678224ba8ce59c79371c74a7ea76ba70c0ac5fa877ca9c35`。

检查结束后删除本轮生成的 5,303 个文件，合计 3,360,967,272 字节（约 3.36 GB），并确认四个生成数据目标均不存在。工作目录中检测到本轮开始前重新导入的 `Untitled` 项目，因此本次使用 `clear-test-data.ps1 -GeneratedOnly`，保留 `.local/workspace`；清理前后的数据库 SHA-256 完全相同，没有覆盖或删除用户新导入的项目。源码、固定回归样本、发行构建和本报告保留。

## 使用

通过 `D:\Codex\furrycad\启动新版FurryCAD.cmd` 启动。打开旧项目后点击“按当前标定重新拆分”，会替换花纹库及相关贴附；已锁定来源会阻止替换。先保留项目副本再对旧项目重新提取，检查待分类区域后继续映射。
